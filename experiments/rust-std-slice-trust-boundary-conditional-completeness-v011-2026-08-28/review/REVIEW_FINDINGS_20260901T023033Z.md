## Blocking findings

### F1: Three canonical `finished=false` defaults lack a source-anchored guard

`tests/test_mutable_iterator_constructors.py:252-297` mutates callback count,
callback state, direction, and inclusive state, but it never asserts or
mutates the canonical `finished=false` value for targets 074, 076, and 098.
The separate finished-state test at lines 323-350 covers only target 093's
empty-slice-dependent value.

An independent in-memory probe changed each of those three constructor
relations from `y_finished = false` to `y_finished = true`. Every changed
obligation remained valid under the generic structural checker and still
returned UNSAT. The target-local validator rejects the current mutation only
by comparing it with output regenerated by the same implementation; if the
generator itself regressed, the existing tests would not detect the
source-wrong default. This is the exact held-back failure that the requested
fail-closed finished-default regression was meant to prevent.

Add a canonical-source-derived literal assertion for `finished=false` on all
three targets and mutate it to `true`, requiring target validation to reject
the result. Apply the same explicit mutation-and-rejection form to the
count/default and nested-constructor-order checks, which currently assert
presence and ordering but do not exercise rejection.

### F2: The reverse Verus models flatten the required constructor chain

The canonical source constructs target 074 through
`RSplitMut { inner: SplitMut::new(...) }` and target 076 through
`SplitMut::new`, `RSplitMut::new`, and
`RSplitNMut { inner: GenericSplitN { iter, count } }`. The accepted target-106
analogue represents its nested private records and invokes each constructor
in order.

By contrast, `tools/mutable_iterator_constructors.py:1424-1700` emits one flat
`MutableIterator` record for every callback target. The resulting
`proofs/074_core_slice_rsplit_mut.rs` and
`proofs/076_core_slice_rsplitn_mut.rs` contain no `SplitMut`, `RSplitMut`,
`GenericSplitN`, or `RSplitNMut` constructor model. They directly initialize
the final projected fields. The SMT names a nested chain, but the requested
source-backed Verus constructor transitions do not establish that the flat
record is the projection of that chain.

Represent the two canonical nested chains directly in Verus, following the
target-106 analogue, or prove and test an explicit projection from equivalent
nested constructor records to the flat observation record.
